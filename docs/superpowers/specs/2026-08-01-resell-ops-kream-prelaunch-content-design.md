# Resell Ops KREAM 플랫폼별 사전 출시 콘텐츠 설계

## 목표

Resell Ops의 첫 플랫폼별 콘텐츠 묶음을 KREAM 판매자의 실제 운영 문제에서 시작한다. 보관판매의 반복적인 판매입찰 확인과 새벽 즉시판매 대기를 각각 독립 검색 의도로 다루고, 현재 구현 상태와 목표 기능을 분리해 설명한다. 모든 공개 문구는 `2026년 8월 오픈 예정`, 카카오 오픈채팅 사전예약, 출시 후 30일 무료 이용을 일관되게 전달한다.

## 승인된 제품·캠페인 결정

- Resell Ops는 현재 `PRE_LAUNCH`이며 설치하거나 실제 KREAM 작업을 실행할 수 있는 공개 배포물이 없다.
- 이번 캠페인의 오픈 예정 시점은 **2026년 8월**이다. 정확한 날짜가 확정되지 않았으므로 모든 공개 문구에 `예정`을 유지한다.
- 조건부 즉시판매는 판매자가 승인한 요일·타임존·시작/종료 시간창 안에서 구매입찰가가 하한가 이상일 때 실행하는 `StandingSellRule`로 정의한다.
- 규칙은 SKU·채널, 하한가, 시간창, 최대 수량, 일일 최대 체결 횟수, 만료일을 고정하며 변경 시 새 승인이 필요하다.
- 실행 직전 가격과 재고를 다시 확인하고, 결과가 불확실하면 자동 재시도하지 않으며 사용자·운영자 중지 장치를 둔다.
- 이 기능은 현재 요구사항만 정의된 미구현 상태다. KREAM 온라인 read/write capability도 출시 게이트를 통과하지 않아 비활성이다.
- 기존 owner당 1회 15일 체험 정책은 owner당 1회 30일로 변경한다. 사전예약 CTA는 이 30일 무료 이용을 안내하되, 별도 독점 혜택이나 현금성 쿠폰처럼 표현하지 않는다.
- 사전예약은 기존 카카오 오픈채팅으로 받는다. 플랫폼 계정, 비밀번호, 쿠키, 주문 개인정보, 결제정보를 수집하지 않는다.

## 런칭 표현과 안전 경계

이번 콘텐츠에서 `오픈` 또는 `출시`는 KREAM 예약 즉시판매가 PRD의 T2 안전·정책 게이트를 통과해 실제로 제공되는 시점을 뜻한다. 구현이나 공식 연동 근거가 준비되지 않은 상태에서 단순 앱 셸 또는 로컬 파일 검증 기능의 공개를 예약 즉시판매 출시로 표현하지 않는다.

공개 문구는 다음 상태를 구분한다.

| 상태 | 허용 표현 | 금지 표현 |
|---|---|---|
| 현재 | `개발 중`, `2026년 8월 오픈 예정`, `사전예약 접수 중` | `지금 사용`, `설치 가능`, `자동판매 실행 중` |
| 목표 기능 | `출시 시 제공 예정`, `시간창과 하한가를 미리 승인하는 방식으로 개발 중` | `KREAM 공식 연동 완료`, `무조건 체결`, `수익 보장` |
| 혜택 | `사전예약 후 출시 시 30일 무료 이용 안내` | `15일+15일`, `평생 무료`, 미정 가격을 근거로 한 할인율 |

2026년 8월 안에 출시 게이트가 충족되지 않으면 공개 글의 예정 문구를 즉시 갱신하고 확정된 것처럼 방치하지 않는다.

## 콘텐츠 묶음

한국어 원문 두 편과 의미가 같은 영어 현지화 두 편을 발행 후보로 만든다.

### 1. KREAM 보관판매

- 가제: `KREAM 보관판매, 판매입찰 가격을 하루 몇 번 확인하시나요?`
- 검색 의도: 보관판매 판매입찰 경쟁, 가격 확인, 보관기간과 비용 판단
- 핵심 문제: 상품 수가 많아서가 아니라 판매입찰 가격 위치가 바뀌어 반복 확인이 생기고, 보관기간·비용·예상 실수령을 함께 판단하기 어렵다는 점
- 사실 경계: 경쟁 강도를 근거 없는 수치나 보편적 사실로 단정하지 않는다. KREAM 공식 FAQ로 확인되는 판매입찰 구조, 최대 보관기간, 현재 비용 정책만 검증일과 함께 인용한다.
- 실용 가치: 수동으로도 사용할 수 있는 `입찰가·관측시각·예상 실수령·보관기한·비용` 점검표를 제공한다.
- 제품 연결: Resell Ops가 가격 관측, 비용 가정, 보관 상태를 한 화면에서 판단하도록 개발 중이라고 설명하되 현재 실행 가능한 기능처럼 쓰지 않는다.

### 2. 새벽 예약 즉시판매

- 가제: `새벽 즉시판매 때문에 알람 맞추시나요?`
- 검색 의도: KREAM 즉시판매 예약, 새벽 구매입찰 대응, 자동 즉시판매 안전장치
- 핵심 문제: 특정 시간대의 구매입찰을 확인하기 위해 사용자가 깨어 있어야 하는 운영 부담
- 제품 설명: 한 시각에 무조건 누르는 매크로가 아니라 `요일·타임존·시간창 + 하한가 + 수량·횟수·만료 제한`을 사전 승인하는 방식으로 설명한다.
- 안전 설명: 실행 직전 가격 재확인, 재고 예약, 불확실 결과 재시도 금지, kill switch를 포함한다.
- 상태 표시: 본문 첫 제품 언급과 CTA 근처에서 모두 `출시 시 제공 예정·현재 미구현`을 명시한다.

두 주제 모두 기존 Resell Ops 글과 내부 링크로 연결하되 같은 서론, 같은 단계 수, 같은 FAQ를 복제하지 않는다. 영어판은 KREAM 고유 개념을 보존하면서 직역투를 피하고, 기능 상태·출시 예정·30일 혜택은 한국어판과 동일하게 유지한다.

## 플랫폼명·브랜드 사용 정책

KREAM 등 플랫폼명은 공식 기능을 설명하는 사실 기반 제목, 본문, slug, SEO 키워드와 태그에 사용할 수 있다. 기존의 플랫폼명 전면 금지 규칙은 이 편집 목적에 맞게 좁힌다.

다음 제한은 유지한다.

- Resell Ops 제품명에 KREAM을 결합하지 않는다.
- KREAM 로고·BI·앱 화면을 허가 없이 사용하지 않는다.
- 공식, 인증, 제휴, 파트너 또는 승인된 자동화라는 인상을 주지 않는다.
- 플랫폼 정책을 우회하거나 CAPTCHA·OTP를 자동 해결한다고 표현하지 않는다.
- KREAM이 제공하는 기능과 Resell Ops의 미출시 기능을 한 문장 안에서 혼동시키지 않는다.
- 글 하단에 비제휴 고지를 넣고 공식 FAQ 링크를 직접 제공한다.

## CTA 설계

기본 CTA는 다음 사실을 포함한다.

> Resell Ops는 현재 개발 중이며 2026년 8월 오픈 예정입니다. 카카오 오픈채팅으로 사전예약하면 출시 후 30일 무료 이용을 안내해 드립니다.

CTA는 기존 캠페인 식별자와 카카오 오픈채팅 링크를 재사용한다. 오픈채팅에서 받는 정보는 출시 알림과 사전예약 확인에 필요한 최소 범위로 제한한다. 30일 권한의 실제 부여 방식이 확정되기 전에는 코드, 쿠폰, 자동 등록 또는 즉시 활성화를 약속하지 않는다.

## 제품·마케팅 동기화 범위

### 제품 사실 기준

- `prd/resell-ops/requirements.md`: 무료체험 15일을 30일로 변경하고, 조건부 즉시판매를 2026년 8월 오픈 목표 기능으로 명시하되 현재 미구현과 T2 선행 조건을 유지한다.
- `prd/resell-ops/api-spec.md`: `TRIAL` 만료 계산과 계약 테스트를 30일로 변경한다. StandingSellRule의 API 계약이 없다면 구현 전에 별도 계획으로 추가한다.
- `prd/resell-ops/connectors/kream.md`: `listing.create`와 관련 read capability의 `DISABLED` 상태를 유지하고, 출시 체크리스트를 통과하기 전 활성화하지 않는다.
- 백엔드 라이선스 코드와 테스트: `TRIAL_DAYS`, 만료 경계, 표시 문구를 30일로 맞춘다. 15일을 기대하는 기존 테스트와 fixture를 전수 검색한다.

### 마케팅 사실 기준

Resell Ops의 `feature-truth.md`, `brand.md`, `audience.md`, `messaging.md`, `channels.md`, `positioning.md`를 다음 기준으로 동기화한다.

- 15일 공개 문구를 30일로 교체한다.
- `2026년 8월 오픈 예정`과 날짜 미확정 상태를 기록한다.
- `StandingSellRule`을 출시 목표이자 현재 미구현으로 함께 기록한다.
- 플랫폼명은 편집·검색 맥락에서 허용하되 제품명·제휴 오인·BI 사용은 금지한다.
- CTA를 카카오 오픈채팅 사전예약과 30일 무료 이용 안내로 통일한다.

### 블로그

- 한국어·영어 신규 글 4개와 관련 내부 링크를 추가한다.
- 발행 파일 수와 한영 pair 수를 고정하는 감사 테스트를 새 총계에 맞춘다.
- 제품 상태, 비제휴 고지, 공식 출처, CTA 캠페인 값을 정적 검사한다.
- AI 보조 작성 고지는 실제 제작 방식에 따라 투명하게 유지하되 검색 순위를 보장하거나 불이익을 단정하지 않는다.

## 품질 검토

`content-ops` 패널은 9명으로 구성한다.

1. 콘텐츠 전략
2. 검색 의도·SEO
3. KREAM 판매자 공감
4. 실용성·정보 밀도
5. 제품 사실·PRD 정합성
6. 근거·정책·법적 리스크
7. CTA·전환
8. 브랜드 보이스
9. AI Writing Detector / Humanizer — 1.5배 가중

Hook, Voice, Value Density, Engagement를 각 25점으로 평가한다. 모든 전문가가 90점 이상이어야 통과하며, 미달 시 가장 큰 문제 세 개를 고쳐 최대 세 라운드까지 반복한다. 라운드별 원점수와 수정 내역을 결과에 남긴다.

## 검증

- PRD, API 명세, 코드, 테스트, 마케팅 문서에서 `15일`, `TRIAL_DAYS`, `15 * 24` 잔존 표현 검색
- owner당 1회 30일 만료 경계와 유료 전환 회귀 테스트
- StandingSellRule 상태·시간창·하한가·실행 안전장치의 PRD 정합성 검사
- KREAM capability가 출시 게이트 전 계속 `DISABLED`인지 확인
- 한국어·영어 파일 수, locale pair, frontmatter, 내부 링크, CTA, 비제휴 고지 검사
- 외부 링크와 KREAM 공식 출처의 최신성 확인
- `npm run lint`
- `npm run build`
- 변경 저장소별 diff와 사용자 기존 변경 보존 확인

검증 실패 시 배포 후보로 만들지 않는다. 특히 30일 백엔드 변경 없이 30일 혜택을 현재 사용 가능한 것처럼 발행하거나, T2 capability가 비활성인 상태에서 예약 즉시판매를 출시 완료로 표현하지 않는다.

## 배포 흐름

로컬 수정과 검증을 완료한 뒤 저장소별 변경 목록, 테스트, 콘텐츠 패널 점수, 남은 출시 게이트를 사용자에게 보고한다. 사용자가 다시 승인한 경우에만 외부 push와 배포를 실행한다. 배포 후 실제 공개 URL에서 한국어·영어 글, CTA, 비제휴 고지, 내부 링크를 확인한다.

## 완료 조건

- PRD·API·백엔드·마케팅 문서의 체험 기간이 owner당 1회 30일로 일치한다.
- 예약 즉시판매가 현재 미구현이면서 2026년 8월 출시 목표라는 두 상태가 모순 없이 표시된다.
- 신규 한국어·영어 콘텐츠 네 편이 공식 근거와 비제휴 고지를 포함한다.
- 보관판매 글이 근거 없는 경쟁 강도나 상품 수 증가를 원인으로 단정하지 않는다.
- 즉시판매 글이 단순 시각 예약과 승인된 조건부 시간창을 혼동하지 않는다.
- 모든 자동 검사, 회귀 테스트, lint, production build가 통과한다.
- 콘텐츠 패널 전원이 90점 이상이다.
- 사용자 승인 전에는 외부 발행·배포·계정 변경을 실행하지 않는다.
