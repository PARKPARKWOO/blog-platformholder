# 마케팅 블로그 콘텐츠 품질 개선 설계

## 목표

현재 발행 중인 한국어 원문 21개와 대응 영어 글을 함께 개선한다. 기존 URL과 검색 자산은 유지하면서 사실 근거, 제품 정합성, 메타데이터, 한영 내용 일치도를 높인다. 수정 후 콘텐츠 품질 패널 90점 이상을 목표로 최대 세 차례 검토하고, 사이트 검증을 통과한 변경만 배포 후보로 삼는다.

## 범위

### 포함

- `content/ko/`의 발행 글 21개와 대응하는 `content/en/` 글
- BBR/PocketFit의 `feature-truth`와 충돌하는 상위 메시징 문구
- 기능 기준 메타데이터, 실제 제작 이력에 따른 AI 작성 고지, 내부 링크
- 독립 근거가 필요한 운동·실종동물·법률성·판매 채널 주장
- 현재 포트폴리오와 맞지 않는 Platformholder 소개글
- 변경된 콘텐츠의 lint, production build, 한영 대응, 링크·frontmatter 검사

### 제외

- `_drafts` 및 `_memo`
- 기존 slug, canonical URL, 게시일의 일괄 변경
- 제품 코드나 PRD의 기능 범위 변경
- 확인되지 않은 기능을 콘텐츠 개선 명목으로 공개하는 작업
- 광고 집행, 검색엔진 제출, GitHub push, Vercel 배포의 무승인 실행

## 수정 원칙

### 1. 사실과 근거

각 서비스의 최신 `feature-truth.md`를 제품 표현의 기준으로 사용한다. 수치·법률·플랫폼 정책·건강 관련 주장은 가능한 경우 원문 또는 공공기관 자료에 직접 연결한다. 충분한 근거를 확보하지 못하면 숫자를 삭제하거나 조건부 표현으로 바꾸며, 출처를 만들어내지 않는다.

### 2. 한영 동기화

한국어 글을 기준 원문으로 수정한 뒤 같은 의미를 영어 글에 반영한다. 영어판은 직역하지 않고 독자의 지역 맥락에 맞게 표현하되, 기능 상태·수치·면책·CTA는 한국어판과 동일한 사실을 전달해야 한다.

### 3. 검색 자산 보존

발행 글의 경로와 slug를 유지한다. 내용이 겹치는 글은 삭제·리다이렉트하지 않고 검색 의도를 분리한다. 핵심 글은 종합 가이드, 나머지는 거리·보호소·전단 등 세부 질문을 담당하도록 서론과 내부 링크를 조정한다.

### 4. 사람다운 편집

반복되는 `문제 3개 → 단계 5개 → FAQ` 구조를 글마다 유지하지 않는다. 불필요한 굵은 목록, 같은 결론, 근거 없는 긴급성을 줄이고 실제 상황·판단 기준·예외를 보강한다. 브랜드별 말투와 독자의 행동 단계는 유지한다.

### 5. 메타데이터와 고지

모든 발행 글은 현재 기능 기준을 참조하는 frontmatter를 가진다. AI 작성 고지는 실제로 AI가 작성에 실질적으로 관여한 글에만 넣는다. 제목과 설명은 검색 의도를 우선하되, 현재 공통 가이드의 길이 기준과 한국어 가독성이 충돌하면 억지로 늘리지 않고 해당 불일치를 검증 결과에 기록한다.

## 작업 단위

1. **기준 정리**: BBR 메시징과 feature truth의 충돌을 제거하고 세 서비스의 최신 기준일을 확인한다.
2. **기계적 정합성**: frontmatter, 기능 참조, 고지, 한영 파일 대응을 정리한다.
3. **고위험 편집**: 출처가 필요한 수치와 단정 표현을 수정한다.
4. **구조 편집**: 겹치는 글의 검색 의도와 내부 링크를 분리하고 소개글을 개편한다.
5. **품질 반복**: 9인 패널로 평가하고 90점 미만의 상위 세 문제를 최대 세 라운드까지 수정한다.

## 검증

- 발행 대상 한국어와 영어 파일 수 및 대응 slug 검사
- frontmatter 필수 필드와 기능 기준일 검사
- 내부·외부 링크 형식 검사 및 독립 근거 링크 집계
- 금지된 미출시 기능과 과장 표현 drift 스캔
- `npm run lint`
- `npm run build`
- 변경 파일 diff와 저장소 상태 검토
- 콘텐츠 패널: 전략, 검색 의도, 독자 공감, 실용성, 제품 사실, 근거·리스크, CTA, 브랜드 보이스, Humanizer(1.5배)

검증 실패 시 배포 단계로 넘어가지 않는다. 출처 접근이나 사실 확인이 불가능한 항목은 미검증 상태로 명시하고 단정 표현을 제거한다.

## 배포 흐름

검증 완료 후 변경 요약, 점수, 잔여 위험을 사용자에게 보고한다. 사용자가 배포를 다시 승인하면 커밋을 확인하고 `main`을 GitHub에 push한다. 연결된 Vercel 배포 상태와 실제 공개 URL의 주요 페이지를 확인한다. 검색엔진 IndexNow 제출은 배포와 별개의 외부 작업으로 간주하며, 필요하면 별도 확인 후 실행한다.

## 완료 조건

- 한영 발행 글의 기능 주장과 핵심 행동 지침이 서로 일치한다.
- 근거 없는 고위험 수치가 남지 않거나 조건과 한계가 명시된다.
- 현재 feature truth와 충돌하는 확정형 제품 표현이 없다.
- lint와 production build가 성공한다.
- 콘텐츠 패널 점수가 90점 이상이거나, 세 라운드 후 남은 제한을 구체적으로 보고한다.
- 사용자 승인 전에는 push·Vercel 배포·IndexNow 제출을 실행하지 않는다.
